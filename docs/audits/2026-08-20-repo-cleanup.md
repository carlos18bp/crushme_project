## Security Blocker

The credential formerly present in `backend/setup_db.sql` matches the active
production database credential. The secret has existed in Git history since
commit `9bda4ba`; deleting the file from the current tree does not revoke it or
remove it from history.

Before CrushMe can leave `modernizing`:

1. Rotate the production database credential in a controlled maintenance step.
2. Update the protected credential store and deployment environment atomically.
3. Restart and health-check the web and Huey services.
4. Purge the secret from Git history or document an explicit risk acceptance.
5. Run a repository secret scanner against the rewritten/current history.

Production runtime was not changed during this cleanup.
